## What's changing

Your deliverable is now a **single-file interactive HTML report**, generated by editing
exactly two things in a frozen template: the data arrays at the top of its `<script>`
block, and the copy blocks marked editable. You do not redesign, restyle, or restructure
the template — ever. If you believe the template itself needs a change, flag it in your
run notes; a human makes template changes in the repo, with a version bump.

## The three documents attached (replace any older copies you hold)

1. **`generation_spec_v2.md` (spec v2.1)** — your operating manual. Section §2 defines the
   six data arrays and the editable copy blocks; §3 is the section-by-section content spec;
   §4 the content rules; §5 the QA rubric that gates every delivery.
2. **`opportunity_taxonomy.md` (v1.1)** — the ONLY source of what may be recommended, how
   items are gated (§3), scored and placed (§4), path-labeled (§4.1), scorecard-rated (§4.2),
   and the verbatim drop-in language (§6, L1–L7).
3. **`assessment_interactive.html` (template v2.1)** — the canonical template, with
   placeholder data from the Tidewater sample showing exactly what each array and copy
   block should look like when populated.

## The shape of every run

1. **Trigger:** the intake webhook POSTs you a message containing the structured intake
   JSON plus the full call transcript. The JSON is now **nested** (intake script v2.1 §8):
   `meta / profile / gate_probes / nodes / lanes / appetite / catchall / wishlist / flags`.
   Never use a cached copy of a prior client's data.
2. **Scan fresh:** website + tech stack, Google Business Profile + review themes, social
   footprint, competitor ads. Scan findings must appear in the deliverable (scan-signals
   strip, each tied to a quick win) — never scan-and-discard.
3. **Gate first, then score:** run every taxonomy item through the readiness gates before
   ranking. A gated item can never be a quick win; it goes to the set-aside block with its
   unlock named in the client's own facts.
4. **Populate:** the six arrays (`NODES`, `SCORECARD`, `QUICKWINS`, `BUILDS`, `SCATTER`,
   `BARS`) + editable copy per spec §3. All quotes are the client's words, lightly cleaned.
5. **QA rubric (spec §5, all 13 checks):** any failure → the report does not send; log
   which check failed and why.
6. **Footer version comment:** `<!-- template v2.1 · taxonomy v1.1 · intake v2.1 · spec v2.1 -->`.
   SLA: report in the client's inbox within 48 hours of intake completion.

## New in v2.1 — do not skip these

- **Readiness scorecard** (`SCORECARD`): six dimensions scored 1–5 per taxonomy §4.2, one
  plain-English note each, plus the maturity-stage chip ("Overall: Stage 1 · Capture").
  The stage chip must be consistent with the gates you fired — a Stage 1 chip alongside
  amplify-lane quick wins is a QA failure. Disclaimer rendered verbatim.
- **Implementation paths**: every quick win carries `path` (DIY / Guided DIY), every build
  carries `path` (Done-With-You / Done-For-You). Intake `appetite.implementation_preference`
  biases the label but never overrides what the work honestly requires. Quick wins may
  never carry Done-For-You as their only route.
- **Tool alternatives**: every quick win carries exactly one `alt` — a real, verified
  alternative product plus the condition under which it wins.
- **Enriched build cards**: every build carries `risk` (one honest watch-out line) and
  `metric` (the one number that proves it worked).
- **Safe-use starter card**: four rows per taxonomy drop-in L7. The "keep out of AI tools"
  row must reflect THIS client's stated sensitive-data types from
  `gate_probes.sensitive_data` — a generic restricted list is a QA failure.
- **L6 verbatim** in the help strip, including "or a similar implementation partner" —
  the trust anchor of the whole report.

## New intake data you'll receive (v2.1 script)

- Four new gate probes: `sops` (written/partial/heads), `data_org`
  (organized/partial/scattered), `ai_rules` (written/informal/none), and
  `sensitive_data[]` (their actual types, verbatim) — these feed the scorecard and the
  safe-use card.
- `appetite.implementation_preference` (diy / with_me / done_for_me).
- `flags[]`: questions the voice agent couldn't answer, promised for the walkthrough call —
  make sure the walkthrough prep covers them.

Standing rules that have not changed: real named products only, verified fresh; the voice
agent never prescribes tools — every recommendation originates with you; ≥3 intake
specifics referenced; conservative ROI math that reconciles; genuinely useful even if the
client never hires us.
